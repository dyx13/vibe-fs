# planning — WHY

SWELoop 模式的阶段门依赖生产者自评，容易被模型游戏或陷入死锁。自评说「我完成了」不构成质量证据；质量必须由使用上一任产物的下一个跑者在行动中暴露。把阶段门改成 review 硬门：每一任评「离下一里程碑的 gap」而不是自评完成度，第一任与后任同一标准，前人栽树后人乘凉。findings 空集才晋级，非空即留任并成为修复义务；每任恰好一次，禁止自证。阶段推进因此只有一个入口，接力只换人不换阶段。

规划的价值最终要由执行兑现。交付不再是一个自封的终点：持权 deliver 把底稿全文交给一个真实启动的 Manager 执行会话，规划与执行分离，规划者不假装执行，执行者从底稿出发。交付后的 reprompt 重开沿用原任期，让用户可以在同一工作上继续迭代，而不是被迫另起炉灶。

问用户不需要挂起状态机。两段式 ask 与 Continuation 回送协议是为「等用户」再造的一套流程状态，形式主义多于价值：Plan 是唯一允许空停等用户 prompt 的 role，空停即自然停止，用户下一条 prompt 就是回答。provider error 仍走既有恢复，自然停止与失败恢复的边界由回合分类承担。

在同一物理会话内实现接力式规划，需要明确切分信息边界。跑者拿到的材料严格限于用户原始诉求（U）、上一任期的工作摘要（LWR_prev）以及逐段长成的规划底稿（P）。P 是模型唯一可写的持久化产物，其余材料均由系统生成，杜绝「消息里一份、文件里一份」的双重真相。

交接收缩可见消息集并触发前缀重锚，每一任的上下文保持紧凑专注。交付门是底稿成功落盘的事实门，不再使用虚饰的质量证书，也不再进行无谓的读回校验；授权来自 S3 的 review 空集，交付即成终态且回执不再调模型，保证规划产物具备充分的多任期审视与不可逆的完工确定性。
