## 运行

structured-workflow-012 分别验收日常局部迭代和纯业务模块的独立编测能力。日常允许首次完整构建建立基线，后续沿用新鲜的canonical dist与现有选文件运行器，不要求每次清空目录。纯业务模块还须从没有本项目既有编译产物的空输出目录，仅带自身声明的必要依赖和资源，真实Fable编译、加载本次局部产物、运行对应模块测试并再次修改验证；不以前置全仓构建或canonical dist为条件，工具链和第三方依赖可预先安装。物理adapter只准备必需环境，联合集成测试与完整发布保留完整环境。

两条路径都须证明实际编译范围、产物新鲜度和对应命题执行，并满足 verification-system-016 的固定输入要求；只选跑文件或只有隔离编译、模块加载探针不能代证真实模块行为。011的全部分片独立编译证明另行验收，不由首次完整构建代证。现有入口可复用，不强制新增CLI或运行器。纯业务模块空目录编测能力尚待施工计划R09分批交付；下面的日常命令不代表它已经完成。

暖路径的首个验收链为“A调用B，C调用A”：只改A的普通实现且有效接口稳定，实际只重新生成A，B和C沿用已有产物，C的相关行为测试观察到A的新行为。改变A的公开接口、inline实现或编译期常量时，真实受影响的调用方必须重新验证并在需要时生成新代码；B未变仍可复用。补齐接口删除、类型信息传递、生成JS连接变化、编译配置变化、复用产物缺失/不兼容与失败不发布半套产物的正反例。先证明这条路径可行，再推广到其它分片；若暴露合同泄漏，回到原拆分边界修正。此项及全分片接口核对仍待施工，不把此次规范修订写成能力已交付。
