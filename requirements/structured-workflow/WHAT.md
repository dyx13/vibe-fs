# structured-workflow — WHAT

## [001] 原生控制流

业务流程直接使用宿主语言的顺序、分支、调用、资源作用域与有界递归。调用栈承载执行位置，不得把“下一步走向”保存为长期字段或枚举。

## [002] 不建立第二业务运行时

领域 DSL 采用直接执行的 CE 与具名领域操作，不得构造业务 AST 再解释执行，或用 Command/Reply 总线、continuation 状态树及调用序列回放器调度业务。外部协议解码与物理命令的强类型表示不受此限。

## [003] 存储事实，不存储执行位置

DU 与字段只表达封闭的领域词汇、已发生事实的持久证据或单次返回结果。不得在 record、DU、可变存储或跨模块接口中保存、发布执行位置、下一步指令或多个状态的正交乘积；改名、搬移和恢复用途不构成例外。

`Stage`、`Phase`、`Lease`、`Owner`、`Generation` 不得作为流程程序计数器或伪领域状态；除真实物理归属和资源世代外，也不得用于业务状态机命名。同名外部协议与物理句柄在声明处分别标明 `DSL-class: ExternalSignal`、`PhysicalHandle`；`Witness`、`Capability`、`Receipt` 也不得承载执行位置。

同一事实不得重复定义同构 DU；确属不同 bounded context 时明确分界并提供单向转换。恢复从 Journal fold 的事实和当前物理观察重新证明未完成义务，再进入普通业务流程；不得恢复 continuation、临时中间状态或把“最新 case”当作恢复地址。Reconcile 只稳定观察，不接管业务调度；协议 Phase 只能作为只读诊断投影。

## [004] 决策与效果分离

纯决策、领域词汇、端口和物理适配器按 subsystem 的知识边界组织，不另设平级治理身份。composition root 只承担构造、类型化拓扑与模式选择、固定次序、路由、生命周期、排空和释放，不实现其他 subsystem 的决策、恢复或分类，也不存储执行位置或动态管道。

副作用通过具名 capability 调用，不以泛化总线抹平类型边界。控制分支不得嵌套第二层决策树；错误与短路用标准 Result/Option 组合子展开，复杂决策提取为独立具名责任。

## [005] 可变存储的用途

可变存储仅承载局部算法草稿、并发同步、投影缓存或物理句柄，不记录业务阶段、执行槽位或行为布尔值。物理可变存储必须显式标明用途。

## [006] 组合闭包与合法状态

包含两类以上状态控制轴的数据结构，必须证明每个可达组合有确切业务含义并完成分类，否则拆成独立流程或显式 capability。父流程只接收子流程的类型化输入、领域结果和能力证明，不观察或保存其执行位置，也不通过 Advance/Tick/Step 轮询驱动它。

模块接缝和跨回调注册必须携带明确的物理或能力证明，不得退化为状态调度总线。外部协议需要 step/nextTool 时，例外必须写入规范：kernel 独占 continuation、closure 与停止权，外部调用者只提供观察。

## [007] 具名领域操作

复杂时序封装为有明确领域承诺的具名操作，由一个 subsystem 拥有并提供时序或行为证明。封装不改变宿主 CE 直接调用的本质；正确性由可观察效果、事实、调用轨迹、端口交互和最终状态证明，不以解释器 AST 节点代替。

## [008] 改变 trace 的组合

资源与诊断作用域可以透明地调用传入操作一次，但不得改变结果、次数或权威。重复调用、恢复或回退等改变 trace 的组合，必须有明确 subsystem、WHAT 依据、允许的 trace 关系、可执行证明、有限边界及失败/取消/deadline 策略，并在调用点具名。

不得引入泛化 middleware/decorator 接口、动态注册或匿名全局框架，也不得以中央运行时替代普通 CE 重入。

## [009] 取消属于控制面

取消与中断控制程序是否继续，不得伪装成业务终态写入结果数据流。

## [010] 有界循环与并发

业务循环、重试与并发扇出必须有界。并发扇出统一通过 `Parallel.mapBounded`，指定正有限上限、保持输入顺序、传递取消，并在异常时立即拒绝且归还许可；不得默认无界运行。

## [011] subsystem 与编译归属

subsystem 是唯一人工治理的架构单位，拥有领域词汇、不变量、失败语义、决策、公开合同和行为证明，并能仅依赖公开合同及证明被整体替换。每个生产 `.fs` 恰属一个 subsystem、恰由一个 compile shard 编译，且与对应 `.fsi` 同 shard。

compile shard 只承担编译隔离和优化，可独立拆并，不取得语义所有权、调用授权或生命周期。每个 shard 显式声明 `WanxiangshuSubsystem` 与 `WanxiangshuCompileShard`；ProjectReference 图必须为 DAG，全部生产源与分片声明精确对应。

独立编译的判定单位是现有 compile shard；领域合同仍由 subsystem 拥有。每个分片的公开类型、值和函数由所属 `.fsi` 定义，依赖提供方与反向消费者从现有工程声明派生。有效编译接口还须覆盖调用方生成代码使用的 inline 实现、编译期常量、影响代码生成的属性，以及生成 JS 的导入路径、导出名称和调用约定。仅有 `.fsi` 配对或签名字节未变，不能代证有效编译接口稳定；合同遗漏或实现泄漏必须在原边界修正，不以新共享桶或手工符号权限表补洞。

生产编译集合由分片清单和 canonical order 共同确定，顺序由 `compile-order.txt` 声明并覆盖全部源，不依赖 wrapper 工程。发布检查依据这些构建事实，不另建 owner/locality 或符号 ACL；FCS 扫描限制见 verification-system-018。

独立编译的完整证明必须覆盖当前清单中的每个 shard：以该 shard 为根，仅使用其声明的前向依赖闭包，经真实 Fable 编译成功。最大闭包、若干代表根或全仓合并编译不能替代其余根的证明。可复用的编译证据必须属于同一根及完全相同的有效输入，包括源与签名、工程与导入配置、编译脚本、资源、编译顺序、条件定义和工具链；任一相关输入变化即失效，新增 shard 不得漏项。

## [012] 精确增量编译

构建必须区分读取/检查的输入集合、需要重新生成代码的分片和复用既有产物的分片。前向源码依赖闭包可以是 Fable 读取/检查所需的输入，不能据此认定整个闭包的产物失效。工具链、编译配置及生成模块的连接方式兼容时，普通实现变化而有效编译接口不变，只重新生成改动分片，复用未变的依赖及调用方产物；重新运行相关行为测试不等于重新编译这些调用方。

签名、inline/编译期常量或其它有效编译接口变化，必须沿真实消费关系检查调用方，必要时传递；接口传递使用的类型和编译信息也须计入。消费关系由现有分片依赖图派生，可先保守选择反向消费者，不要求新增逐符号使用数据库。判定须比较前后版本，不能只扫描修改后的源码而漏掉删除的 inline 或常量。无法证明接口稳定时明确说明原因并扩大检查，不能把“已声明依赖”直接等同于“每次都要重编”。

接口判定、实现输入和产物兼容信息须分别绑定同一构建快照；未变依赖允许复用，与全输入变化后旧的独立编译验证结论失效是两件事。所有复用产物必须有匹配的来源和连接信息，缺失或不兼容时实际重建，不以文件存在或输出字节相同冒充已复用。

源新增、删除和移动必须实际影响选择；未归属的生产源报错，不以全量编译代替登记。工程、工具链、锁文件或 Fable 配置变化可保守全量；文档、资源、测试按真实输入关系更新派生产物和检查，不必调用 Fable。

编译输入先求并集，再按 canonical order 交给现有 Fable 路径，不逐 shard 重复启动；缺少显式顺序时由 DAG 拓扑推导。允许使用零 ProjectReference 的平坦工程提供源码上下文，但不能以此豁免未变产物的复用。具体增量机制须由当前 Fable 的真实编译与行为证明确定，不以移除缓存开关代替验证。完整发布也不依赖 wrapper。分片优化不得改变 subsystem 数量，或把无关知识重新集中到共享基础包。

日常开发必须有可重复使用的局部编译与测试路径，明确所选根、读取/检查范围、实际重新生成与复用的分片及对应证明。新环境允许先经正式入口完整构建，建立开发基线；之后的普通实现修改按必要影响范围实际编译并运行相关测试，连续修改后仍须验证正确，不只证明计划选集正确。日常测试可使用正式构建更新后的canonical dist，或与本次输入匹配的局部产物，不要求每次修改都清空产物。

每个承诺独立开发的纯业务模块还必须能从空输出目录，仅使用自身声明的必要依赖和资源，经真实Fable编译并运行对应模块测试，连续修改后仍可再次验证。空输出目录没有本项目既有编译产物，工具链和第三方依赖可以预先安装；不要求模块零依赖。该能力不以前置全仓构建、canonical dist或打包为条件，测试加载本次局部生成的产物，不从其它构建目录隐式回捞旧产物。日常暖产物路径和仅有独立编译的证明均不能代证它。

两条路径可以共用现有入口，不强制新增CLI或运行器。纯业务测试不启动无关物理环境或打包；物理adapter只准备其必需环境，联合集成测试和完整发布继续使用完整环境。需要扩大编译范围的变化按本条前述规则处理。验证的监督、输入和产物新鲜度遵守 verification-system-006、016、017、021。

## [013] 依赖倒置

跨 subsystem 只依赖所需的窄公开合同、纯数据/决策或 capability port，不读取对方的运行时注册表、工厂、物理句柄、执行状态或适配器。物理能力由 composition 注入，业务依赖端口，适配器依赖外界。

通用平台原语不依赖领域知识；相同语法、基础类型或使用频繁不是合并理由。分片拆分必须减少真实依赖闭包或隔离变化原因，不能只改名或标签。按全部生产 shard 的实际依赖聚合后，subsystem 图不存在非平凡强连通分量，才满足拆分完成的无环要求；分片图为 DAG 不能替代这一要求。

迁移期间必须报告完整的 subsystem 环及其真实依赖边，已迁出的边界立即受编译和行为证明保护。尚存的环不得视为已完成，也不得以长期豁免、遗漏节点或边、facade、总线、service locator 或共享 DTO 包隐藏。

## [014] 物理能力留在边界

文件、进程、网络、Provider、Git、时钟等外界能力各有明确且唯一的物理实现边界。业务只消费注入的窄 capability，不能因复用 helper 取得工厂、可变注册表、Node 导入或具体 Host 实现。

物理适配器及其编译分片仍归所属 subsystem，不形成第二治理身份。安全边界由精确 capability、身份、生命周期和行为反例证明，项目名、internal、标签或注释不能替代。

## [015] 生成物可追溯，不另立架构权威

生成代码与资源必须能追溯到所属 subsystem 和确定输入。digest、lineage 与确定性记录只证明生成正确性，不形成另一套所有权或授权体系。携带外界能力的生成物仍按真实 capability 处理，不能因生成过程确定就视为纯计算；不得另建与源码竞争的 canonical world、裁决快照或符号 ACL。

## [016] 单一结构门禁

发布依据当前 subsystem 结构事实；签名、工程、依赖图、增量编译及编译边界证明是编译资产，额外所有权或分类清单不参与发布裁决。source → subsystem → compile shard 的结构由唯一门禁 `scripts/checks/subsystems.mjs` 校验，不另设平行权威。

该门禁从同一生产清单生成分片图和 subsystem 图，按 [013] 区分迁移期的完整报告与拆分完成后的无环拒绝门禁。静态图检查、真实独立编译和行为证明分别记账，任一项通过不能替代其他项；不得以调整标签或证明范围取得完成结论。

## [017] 插件转换行为证明

插件转换与业务装饰器的顺序和职责由 Host 合同及生命周期拓扑约束，通过 Host 边界契约测试证明；不得另建静态源码扫描替代该行为证明。

## [018] 关键流程的准入与结算

每次关键业务流程的 trace 必须来自一次明确准入，收敛为一次结算或有界的无效果终态，不得重复结算。无法收敛时保留未决或失败证据，不得静默丢弃；准入或结算不成立时，即使局部结果正常也不得判整体成功。

关键业务词汇必须登记所属 subsystem、主导 WHAT、允许的 trace 关系及可执行行为证明，使静态与运行时都能核对这些义务。

## [019] 顺序 Result traversal

顺序 Result traversal 按输入基数有界：mapper 按输入顺序对每个到达项恰调用一次，成功时到达全部输入，首个 Error 原样短路，空输入不调用 mapper。取消和异常原样传播并停止后续调用；该组合不拥有重试、恢复或 deadline 策略。
