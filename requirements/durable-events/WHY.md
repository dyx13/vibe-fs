# durable-events — WHY

事实分散在内存、私有文件和数据库里，崩溃后就无法确定哪个版本可信。统一的追加事件流把“已经发生”与“由此推得”分开；投影可重建，已提交事实在保留窗口内不可改写。整流 retention 限制历史成本，同时避免逐条删除破坏仍保留的因果关系。

Canonical 字节使同一事件身份有唯一含义。冻结已有词汇、以新类型表达新语义，可以避免不同进程用同一个名字解释不同事实。损坏必须拒绝，合法并发则保留；混淆两者会误删事实或在错误地基上继续运行。

单进程独占本地 writer，使日常提交不依赖网络和 Git 历史规模。Git 只在用户远程操作时承担交换。先提交、后发布 Current，保证查询不会看见无法恢复的未来；提交不确定时保留不确定性，比凭异常或内存猜测安全。单进程事件流的物理体量无界增长，而远端交换平台对单文件设硬性体积上限（如 GitHub 的 100 MiB）；有界段序列把物理载体与逻辑流分开，逻辑流的不可变与按序重放不再依赖单文件的物理形态。

共同的 Integrator 防止各领域独自解释历史。纯协议与领域 fold 可以独立验证，物理能力留在外层，消费者便不必为读取稳定契约带上整个运行系统。加载与激活分离，也避免仅启动插件就重放全部历史或写入新事实。

语义拒绝既要留下原因，又不能让坏状态继续传播。持久化 cut 提供下一代进程的接续点，当前进程退出隔离被污染的内存。结算、报告和终止分别有明确所有者，才不会遗漏证据、重复退出或把未确认写入当成未发生。
