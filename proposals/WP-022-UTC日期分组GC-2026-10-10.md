# WP-022 UTC 日期分组 GC 收尾记录（2026-10-10）

- 工作包：WP-022（指南 L601）。波次 W1。
- 意见原文：「按照 UTC 日期进行分组，昨天和今天保留，前天或之前无使用的内容即删除。日期只用于 GC，和语义无关。允许在日期之间移动数据，日期是"最近修改"语义。」
- 本卡范围：核心行为已在实现与条款中（见第一节）。本卡只补两条专测与本记录；不改实现、不改 WHAT、不动其他文件。

## 一、已存在的实现事实

1. 保留判据是 UTC 日历日，不是滚动窗口。
   - `ProcessEventLog.fs:236-243`：`utcDayMilliseconds = 24h`；`utcDayOf timeMs = floor (timeMs / utcDayMilliseconds)`；`isWriterActiveAt nowMs lastActivityMs = utcDayOf lastActivityMs >= utcDayOf nowMs - 1.0`。
   - 今天与昨天保留，前天及更早整体过期。源码注释明确「UTC calendar-day group, not a rolling 24h window」与「a writer's activity may move it to a later day」。
2. 活动时间取 durable 字节，mtime 只是非 Journal 回退。
   - `ProcessEventLog.fs:642-722`、`735-737`：`durableTailActivity` 反向扫描尾部完整行；`JournalEnvelope.payload.ObservedAt` 优先；连续 `ProjectionCutTail` 向前越过后再判定；无 durable 活动时才回退 producer-side file activity（`writerMetadata:762-770`）。
3. 过滤是读口，物理 GC 在同步点。
   - `ProcessEventLog.fs:862-879`：`readStreamsAt` 先过滤整条过期 writer，再按 WriterId 字典序读取（`writerFileNames:739-748` 排序）。`RetentionSurface.fs:19-22` 的 `retainedWriterIdsAt` 是公开读口。
   - `ProcessEventLog.fs:852-857`：`removeWriterFile` 物理删除整文件。
   - `WriterStreamSync.fs:368-376`：`removeExpiredLocalWriters` 在物化时 partition 并删除过期本地 writer。
4. 物化与 manifest 绑定过期语义。
   - `WriterStreamSync.fs:334-341`：`nextExpiry = (utcDay(lastActivity) + 2) * 24h`，即活动 UTC 日的下一日午夜起该 writer 成为「前天」；materialization cache 以该点失效。
   - `WriterStreamSync.fs:378-418`：`materializeLocalAt` 只物化保留集合，写 `writers/` 树与 `writer-manifest`（v2：每个 blob OID + lastActivity），过期者不进入新快照。
5. 条款已成立：`durable-convergence/WHAT.md [011]`
   - `Retain(now, W) = {w ∈ W | utcDay(lastActivity(w)) >= utcDay(now) - 1}`；日期只作 GC 分组、允许移动；`Retain(A ∪ B) = Retain(A) ∪ Retain(B)`；活动来源优先级；`writer-manifest v2` 绑定与旧 manifest 忽略；窗口外 parent 视为已满足因果边界。
6. `durable-events/WHAT.md [007]` 承载本卡的语义前置：「durable-convergence-011 已整体淘汰 writer 中的 parent 属于 retention boundary，不构成缺失父事件。」

## 三、本卡新增的两条证据（未运行）

### 证据 A：三态并存

- 用例标题：`WHAT[durable-convergence-011] today, yesterday, and the day before resolve as three distinct UTC day groups`（`011.test.mjs:367`）。
- 固定 nowMs = `2026-08-21T00:30:00Z`。三个独立 writer 的 Journal 活动：
  - today = `2026-08-21T00:10:00Z`；
  - yesterday = `2026-08-20T00:10:00Z`（距 now 超过 24 小时）；
  - before = `2026-08-19T23:50:00Z`（距 now 不足 48 小时）。
- 断言：`retainedWriterIdsAt` 返回恰好今天与昨天；同步后今天/昨天本地文件保留、远端树在列，前天本地文件物理删除、远端树不在列。
- 覆盖的行为：同一 nowMs 下三态并存的整体保留与整体过期；证明判据是 UTC 日历日，而非滚动 24h 窗口。

### 证据 B：连续跨日期移动

- 用例标题：`WHAT[durable-convergence-011] advancing a writer activity from yesterday to today pushes its expiry one UTC day later`（`011.test.mjs:393`）。
- 固定 day0 = `2026-08-21T00:00:00Z`；writer 初始活动 `2026-08-20T12:00:00Z`。
- 步骤：
  1. 在 day0 + 1 天检查：不推进则整体过期（返回空集），但文件仍在——过滤不删字节。
  2. 追加一条 Journal 事实（parents=[A]），尾部活动推进到 `2026-08-21T12:00:00Z`。
  3. 在同一个 day0 + 1 天时刻：保留集合含该 writer；同步后本地文件仍在、远端树含它——过期点随活动后延一个 UTC 日。
  4. 在 day0 + 2 天检查：整体过期；同步后本地文件删除、远端树不含它。
- 覆盖的行为：日期只是「最近修改」分组，writer 允许跨日期移动；移动原子地改变过期点；再越界后整体退出。

## 四、书面裁决：无使用者删除维持「UTC 日期唯一判据」

- 意见要求「前天或之前无使用的内容即删除」。
- 裁决：不引入引用图追踪、使用者计数或引用扫描。窗口外旧数据的「无使用者」由 UTC 日期窗口本身定义，其语义依据是 `durable-events-007`：
  - 该条款明确「durable-convergence-011 已整体淘汰 writer 中的 parent 属于 retention boundary，不构成缺失父事件」。窗口内 writer 引用窗口外 parent 时，该 parent 被视为已满足的因果边界，不构成使用者关系。
  - 因此窗口外旧数据在语义上无使用者：保留窗口内不存在需要它参与折叠的路径。若为删除再建引用图，等于另建一个与窗口判据平行的第二权威。
- 边界保持：窗口内 writer 内部的依赖缺失或成环仍拒绝（`durable-events-007` 后半句、`durable-convergence-011` 末段）。本裁决不放松窗口内完整性校验。
