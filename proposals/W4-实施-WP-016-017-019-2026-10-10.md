## WP-016 · 最后一任收尾

- 意见：即使通过评审，也允许当前 Manager 继续做收尾工作，并立刻通知它是最后一任，明知后继无人。

### 改动

- `Foundation/OfficeCapability.fs` / `.fsi`：`ManagerCapabilityFacts` 字段 `HasValidBoundCertificate` 改为 `IsFinalIncumbent`；新增 `managerFinishPermissions`（Read / Glob / Grep / Horizon / Join / Finality），并在 `permissionsForManagerFacts` 中以 `IsFinalIncumbent` 分支返回。收尾权限保留读、清理与收口，去掉 Fork / Resume / ReviewAssessment / Sphinx 等一切开新工作能力。
- `Participant/Persona/OfficeCapabilitySurface.fs`：JS 面 `managerFacts` 第三参改名 `isFinalIncumbent`，`factsOfJs` 读同名字段。
- `OpenCode/Tools/ToolRuntimeScope.fs`：`IsFinalIncumbent = road.AcceptedAssessmentFindings |> Option.exists AssessmentFindings.isEmpty`；删除已无消费者的 `certificateMatchesActiveIncumbency`。
- `resources/provider/runtime/manager-finish/{zh-CN,en}.md`：文案改为「findings 为空集 → 你是最后一任 → 可读、清理、收口，不得开新工作」。
- `requirements/relay-assessment/WHAT.md` [005]：改写为「末任收尾」。
- `requirements/capability-enforcement/WHAT.md` [025]：改写为「已接纳评审且仍有 findings、退任冻结或清理阻塞时拒绝；空集 findings 的末任保留只读收尾」。

### 测试

- `requirements/capability-enforcement/tests/025.test.mjs`：
  - P07 改名并去掉「有效证书拒绝」部分，保留清理阻塞与非活跃两部分。
  - 新增 P16（收尾可用）、P17（新工作拒绝）、P18（双语通知文本存在）。
- 既有 P02 / P11 / P12 / P13 / P14 / P15 不受影响：`injectAcceptedAssessment` 注入非空 findings，`IsFinalIncumbent` 为 false，仍走已接纳评审分支。

### 证据状态

## WP-017 · 快照机制去除

- 意见：无必要使用快照机制，乐观认为不会出问题。

### 取舍

- 保留：发布前 `Change/Program.fs · artifactSnapshotMatches`、`gateSnapshotVerdict`、`certifiedEvidence` 与 `Change/Host/Host.fs · loopSignalOfRetirement` 的 Candidate 信号。它们守住发布资格与退休结果。
- 去除：`Fold.fs · checkAcceptedPrerequisites` 的 `RetirementSnapshotStale`（退休快照必须等于评估快照的评审绑定仪式）。
- 一致性由流程与 fast-check 承担；并发改动下不再用运行时快照比对阻断评审与收口。

### 改动

- `requirements/relay-assessment/WHAT.md` [010]：改写为「发布门仍比对当前快照与评估快照，退休匹配仍要求当前证书；不再以快照一变旧评估立即失效在运行时阻断评审与收口」。
- `requirements/change-integration/WHAT.md` [015]：澄清旧证据失效只作用于发布资格，不阻断 Manager 的评审与收口。

### 证据状态

未运行。`relay-assessment-010` 既有测试仍成立：显式 `invalidateCertificate` 后证书 `Valid=false`，`retireAccepted` 因 `QualityCertificateInvalid` 被拒。

## WP-019 · 证书去形式主义

- 意见：处处要证书是形式主义，不变量应由流程 + fast-check 保证，而非运行时到处 fail-closed。

### 逐门裁定

| 门 | 位置 | 裁定 |
|---|---|---|
| finish 精确快照/authority 匹配 | `Fold.fs · checkAcceptedCertificateBindings` | 去除，只留 id / valid / incumbency |
| 退休快照 = 评估快照 | `Fold.fs · checkAcceptedPrerequisites` | 去除（与 WP-017 合并） |
| Continue 不得残留有效证书 | `Fold.fs · admitContinueOutcome` | 去除，改为恒 `Ok` |
| Accepted 后证书有效禁止新任 | `Fold.fs · decideAcceptedReopen` | 去除，改为普通重开 |
| 退休候选精确快照/authority 匹配 | `SuicideTool.fs · qualityCandidate` | 去除，只留 valid / incumbency |
| finish 资源选择的精确快照/authority 匹配 | `Mission/Manager/Workflow.fs · isBoundCertificate` | 去除，只留 valid / incumbency |
| 发布 Candidate 信号 | `Change/Host/Host.fs · loopSignalOfRetirement` | 保留 |
| 发布前快照匹配 | `Change/Program.fs · artifactSnapshotMatches` 等 | 保留 |

### 改动

- `Mission/Relay/Fold.fs`：`checkAcceptedCertificateBindings` 去掉 snapshot/authority 匹配；`admitContinueOutcome` 恒 `Ok`；`decideAcceptedReopen` 直接 `commitPendingIncumbency`。
- `Mission/Relay/OpenCode/SuicideTool.fs`：`qualityCandidate` 只校验 `Valid && IncumbencyId`。
- `Mission/Manager/Workflow.fs`：`isBoundCertificate` 只校验 `Valid && IncumbencyId`。
- `requirements/relay-incumbency/WHAT.md` [006]：去掉「证书有效时禁止新任」与「Accepted 必须匹配评审/证书快照」；[008] 改为「证书只作历史」。
- `requirements/relay-assessment/WHAT.md` [005]：见 WP-016。

### 测试

- `requirements/relay-incumbency/tests/006.test.mjs` 第二用例改写：Accepted 关闭本任后，普通 `openIncumbency` 直接开启下一任，不再要求先失效证书。
- `requirements/relay-retirement/tests/007.test.mjs`：原「Accepted with a stale different snapshot fails」改写为「Accepted retirement 不再要求退休快照等于评估快照」；原「Accepted road cannot reopen while certificate is valid」改写为「Accepted 直接开启下一任，无需失效证书」。
- `relay-assessment/tests/010.test.mjs` 行为不变（显式失效仍阻断 Accepted），未改。
- `relay-incumbency/tests/005.test.mjs`、`008.test.mjs` 不受影响：退休不可逆与 authority 修订使证书失效仍成立。
