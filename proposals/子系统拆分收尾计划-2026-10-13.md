## 二次复核：目标是否足以验收

`29acfeed8` 中的初版计划不足以保证“每个模块可以独立编译，方便开发和测试”：它只要求关键根的编译证明，并未交付不依赖全仓产物的局部测试入口。其解环方向仍可用，但下列补充是整体收尾条件，不能留作可选优化。

| 原始诉求的可验收含义 | 本计划的完整交付 |
|---|---|
| 编译独立 | 按最终inventory覆盖每个实际shard；每个根仅使用自身声明的源码依赖闭包实际编译。R08允许按完整输入身份复用证据，不允许大工程代证小根 |
| 开发和测试局部 | R09提供受监督的显式选根/选测试入口。纯模块从空scratch也能编译并运行真实模块测试，不要求先有全仓dist、OpenCode或package；物理adapter只启动其必要依赖 |
| 业务可替换 | 每个承诺独立开发的领域以同一公开合同接测试capability，运行原生产决策/工作流；不装外域runtime，不复制算法。映射沿用现有fsproj与NNN测试，不建第二权限表 |
| 局部结果可靠 | 实现、签名、inline、源增删等真实迭代保留正确影响范围；局部与完整构建结果一致，最后同候选发布通过 |

这里的独立编译包含必需的源码依赖，不承诺独立DLL，也不承诺任何修改都只编一个文件。集中Journal、跨域原子提交、全局装配仍需要聚合知识；底层公开签名变化可能影响许多真实消费者。当前CanonicalEventCodec的签名变化带入743个实现文件，就是需要如实保留的宽影响样本，不能靠弱化签名检查变小。

二次复核基准的274个根中，188个声明闭包不超过100个实现文件，205个不超过185个；15个超过全仓775的60%，其中13个属于app、1个durable、1个Sphinx。宽闭包主要集中于装配和混合接口，说明拆分有可用基础；这些计数不证明声明自足、行为正确或实际提速。

### 难链与必须先过的小证明

以下为二次复核时列出的困难链条，先做实际合同和最小生产调用链的正负编译、必要行为反例，再迁大批消费者。Change Program 和 Recovery 的小证明现已通过；其它切口仍按各包实际结算，不能把“存在拆法”写成“拆法已验证”。

| 难链 | 难度与容易失败的改法 | 前置小证明及归属 |
|---|---|---|
| Change Program → Types/Journal → durable；Job → WorktreeResource → app | 很高。现有ProgramDeps仍公开AgentFact/ProjectionSet；把Program直接放回change会重新成环 | R07e先拆Change事实/视图、同revision恢复视图、worktree身份与释放能力，隔离Create/Adopt。真实发布、CAS miss、cleanup失败、claim恢复三分支在新合同下通过，才迁Program/Recovery |
| Wire → AttemptPlan(dispatch) → Context；Provider recovery → Blogger/Journal/Host | 高。把Wire整片归context会形成context→dispatch→context；把函数参数改名为port也不会消除类型和事务耦合 | R07a固定跨域attempt编排留dispatch，context只保留本域纯输入/决策。R06/R07b保一份同revision视图、read→wait语义与原子commit；不拆成独立store或多次append |
| ProcessEventLog → 活动时间解释 → Journal；Integrator/Hook共用读取 | 高。只为Hook注入策略会造成两种retention；让底层直接引用durable会扩大环 | R04先定不含Journal类型的必需tail分类策略，覆盖boot/replay、refresh、Hook本地物化、remote import四个根。同一冻结writer/manifest输入、同一截止时刻下选出的保留集合必须一致 |
| Sphinx Bind → CanonicalIntegrator，经app借到依赖 | 高。移走OpenCode接线后补上这条真实引用，会产生durable→interaction→sphinx→durable | R05c先拆rules/Current读取、Commands、durable factory、启动接线四根；前两根不取得durable工厂。R04的构造合同先于这一步定好 |
| Provider SessionSnapshot → Host MessagePart → 跨域投影/回合观察 | 中高。Host transport、Provider wire、Provider semantic消息与持久化trace各有不同含义，不能直接替换DU | R02先列SessionSnapshot、Turn Observation、CompletedTurn和Capture的逐字段消费者/转换，保tool call身份、Activity过滤与既有消息字节；取得纯consumer编译证明后迁合同 |
| Delegation PTY → Process运行时；Git Gateway → 默认ProcessRunner | 中。PtyTypes还含TaskCompletionSource，Gateway还公开createDefaultRunner；换成contract标签不解决问题 | R03只抽请求/结果与必需PTY词汇；R07e把已有注入式converge与物理默认runner分离或保持诚实的adapter边界，不将整份Gateway下沉persistence |

对应直接证据：Change [Types.fsi](../src/Wanxiangshu/Change/Types.fsi) 60—71、[Job.fsi](../src/Wanxiangshu/Change/Job.fsi) 14、[WorktreeResource.fsi](../src/Wanxiangshu/Git/WorktreeResource.fsi) 17—27；Sphinx [Bind.fs](../src/Wanxiangshu/Sphinx/V2/Composition/Bind.fs) 24—57；Wire [Wire.fsi](../src/Wanxiangshu/Context/Prefix/Wire.fsi) 19—24及[WirePort.fsi](../src/Wanxiangshu/Context/Prefix/WirePort.fsi) 24—33；Process [PtyTypes.fsi](../src/Wanxiangshu/Process/PtyTypes.fsi) 84—88、[GitGateway.fsi](../src/Wanxiangshu/Git/Gateway.fsi) 17—29。

## 全程限制
