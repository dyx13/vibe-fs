# 规范施工 Prompt

具体 TODO 任务与顺序见[现行施工总计划](TODO施工总计划-2026-10-03.md)。本文提供通用整理方法，不沿用[归档计划](archive/README.md)的旧站序和候选清单。

用于逐站整理 requirements 中一个模块的 WHAT、WHY、tests。由 02 模块施工经验形成；先遵守本次用户给出的范围、决策方式和提交节奏，不把历史互动流程当成永久审批要求。

测试与验收遵守 [verification-system/WHAT.md](../requirements/verification-system/WHAT.md)。需要补充已有测试 prompt 时，可直接追加[测试效率补充段落](高效测试Prompt.md)。

## 任务

把本模块整理为简短、准确、可执行的规范。WHAT 是权威规则，WHY 解释目标与取舍，tests 提供可反驳的证据。开始时检查工作区差异、相邻模块和已有决定；保护其他人的未提交修改。

## 判断顺序

1. **从必要目标出发。** 先问旧条款保护什么，违约会破坏什么，是否已有条款覆盖。旧文、实现、失败测试都是调查线索，不能反过来证明某个要求必然正确。无法说明必要性的清单不默认逐项保留。
2. **找到唯一所有者。** 按规则实际约束的对象归位。迁移前核对主体、触发条件、范围、数量、顺序、失败后果与例外权；目标条款必须承接仍有效的义务。保留编号，废止编号不再使用。
3. **写最小充分规则。** WHAT 说明什么合格、什么不合格，以及确有必要统一的方法。具体不等于实现细节：虚拟时间、完整记录边界等可能就是合同。辅助函数、日志装饰、代码目录等可替换选择不写成普遍要求。
4. **检验必要一致性。** 两种实现都满足现有文字，却不能互操作或使证据不可比较时，找到真正需要统一的对象和边界，明确写入其所有者的 WHAT。不能只写“保持一致”，也不能让 README 或测试偷偷决定唯一合法方式。
5. **用正反例检验文字。** 检查合规替代实现能否通过、真正违约能否被拒绝。分别标记表达整理、所有权迁移、规范修订；不能把范围或强度变化伪装成润色。例子用于消除歧义，不必全部进入正文。

## 配套文件

- WHY 解释为什么需要这些边界以及取舍，不复制一份规则清单，不增加义务。
- tests/README 解释当前设施、实际用例、运行方式及证明范围。通用概念可以配例子，但必要定义不得只放在这里。
- 每项测试说明失败违反哪个正式要求、反例如何触发。主归属按实际证明对象判断，不沿用旧文件名猜测。移走无关测试时保留有效行为覆盖并核对运行入口。
- 语义测试优先驱动公开行为；静态规则使用同一个检查器验证合规和受控违约输入。不要另造一个只在反例测试里出现的正则假装检查器可红。
- 不能机械判断的 oracle 独立性、语义重复和证明完备性列为人工审阅；不靠词形扫描、固定样例数量或“每条一个测试文件”凑齐。
- 同时试合规替代方案和违规样本。普通业务字段碰巧同名、文件后缀或目录名称相同，都不能直接证明语义相同；被测源码数据也不等于测试执行代码。检查器的便利分类不得变成隐藏规则。
- 分开登记、引用、执行和行为证明。登记正确或代码含 import，不表示入口已执行；链接和加载成功也不表示业务正确。对 Promise、函数和不透明句柄说明当前检查实际观察到了什么，不把载体合法当成结果已验证。
- 审查先固定版本。主目录的施工稿、PR提交和未完成上游合并可能不同；将结论绑定到具体提交及工作区。切换前保存未提交现场，有用记录归档，旧产物通过正式构建更新。
- 覆盖检查必须命中真实调度入口。废弃清单即使与测试文件完全一致，也不能证明实际入口会执行这些文件。先用真实入口的计划与独立声明集核对，再取得对应执行结果；反例先证明完整夹具能通过正常输入，排除缺依赖、旧过滤器或任意异常冒充正确拒绝。
- 检查物理证据是否来自同一被测执行。父进程提前写好数据、子进程只打印成功或任意异常导致非零退出，都不能替代“该子进程完成提交并按规定终止”。设计能区分目标机制和偶然失败的反例。
- 生命周期证明必须实际跨越所声称的边界。重复读取同一绑定不是接力，比较两个字面对象不是接收幂等，关闭空资源不是在途清理。判别器能区分合成样例，只证明判别器的这些分支；没有生产执行记录时，不得以此宣称 Agent 行为合规。
- 删除伪证明时保留仍有效的义务，明确转为 GAP 或 TODO，并检查引用它的发布清单。不要为了绿色重定向到任意现存测试，也不要把自建模拟器与自建答案相互吻合算成产品证明。
- 全量成功不能代替独立边界成立。全量编译可能恰好带上未声明的依赖；局部编译的计划和文件清单也不能替代真实编译。遇到这类失败，保留失败样本、找到缺失的正式依赖，再用同一局部输入验证修复，不靠改成全量掩盖。
- 区分新建与历史解码。修复活跃准入后，旧测试若依赖已废止身份，不可恢复宽松准入以让测试变绿；逐项确认是在新建当前任务还是恢复历史，再更新前者的 fixture，保留后者的兼容证明。保护必须落在生产领域边界，不能只补测试 Surface。
- 字面相同和语义相同是两件事。完整目标资源比较可以证明选对了资源，锚点/占位符/标识符比较可以证明结构对应；它们都不能证明译文或职责含义正确。不要为声称机械完备而锁死措辞，也不要把测试中新造的正则当成生产检查器。
- 检查测试输入是否真正进入被测接口。只测“应该相同”的两个输入，可能因为字段拼错而同时被丢弃；再改变一个必须影响结果的合法字段，证明接口确实消费了它。Surface 若自行复制领域算法，也不能代替实际生产入口。
- 编译成功、清单新鲜和产物目录非空，不等于本次源码已生成。改变所选闭包或实现后，直接检验新产物及其行为；缓存隔离按缓存实际存放位置判断，不能只因工程路径带 fingerprint 就假设共享输出里的缓存也隔离。
- 故障注入须落在要证明的边界。测试接缝可能把 launcher 异常转换成非零退出，这与 Host 创建失败不同；先查清转换，再断言相应结果及资源归还。不要为错误的失败预期改产品。
- 计量先确定对象。原文、包装后结果、内存缓存和单次传输预算不是一件事；测试实际计量规范规定的完整对象，并覆盖多字节边界。若预算连必要事实都装不下，记录合同分岔，不能悄悄省略事实或放宽上限。
- 幂等须比较同一次发生的完整有效材料。“已有就返回成功”可能隐藏冲突，“正文一样就去重”可能丢掉两次实际发生。先分别验证相同身份重放、相同身份变更和不同身份同文，再核对真实入口是否采用领域裁决。

## 完成与交接

规范定稿、测试执行、实现达标分别记账。能直接解决的问题先闭合；会改变用户意图、架构取舍或必要边界且无既有依据的分岔，写清选项、建议及影响，按用户约定的时机集中讨论。第一性原理说明需要解决什么，不自动决定唯一实现。

到约定节点运行受影响的正式检查。保留已确认失败，不选取偶然重跑的绿色结果。报告原定与实际范围、跳过及缺失原因；局部成功不是整体验收。已知反例作为失败或明确 TODO 保存，不计入通过；同步 GAP 与施工记录，避免下一个 Agent 把“文件已整理”误读为“所有要求已实现”。

交付简洁的改动摘要、证据与剩余决定。提交、推送、发布遵守用户本次约定，不在每次改词后自动触发。

新增经验：局部拒绝不等于整链幂等失效，局部容忍也不等于上层会接纳；先追到真正的准入与提交点。故障测试要确认越过了哪道门，提交时的假 digest 被拒绝，不能代替提交后 payload 损坏的读取测试。分段摘要若跨越记录边界，不能靠字符串截断或丢弃摘要解决；先找可验证的因果映射，明确原文重物化与 coverage 的合同关系。

新增经验：两种语义轴必须用能区分它们的反例证明；清空同一集合再重填不是轴已独立。局部接缝要只翻译数据，不能自写一套协议再测自己。故障用例必须定位实际失败层：访问已关闭句柄就被拒绝，不能证明后续 append 的原子性。重放对比要使用相同初始事实，先后调用造成的状态变化不应被误判为别名差异；跨 session 隔离也不等于同一容器内跨 life 隔离。

新增经验：独立调用各自通过，不能拼接成一次真实执行的因果链。索引、测试文件存在、实际用例执行、行为证明分四层核对；状态写着“已修复”也不能豁免证据。正式 runner 自身也要接受缺失文件和加载失败反例，文件 wrapper 完成不等于其测试成功。

### 因果连线不能由测试标题补齐

检查“重启、恢复、全程”的测试时，要追踪实际输出是否进入下一阶段。传入一个 restart 字符串、换一个观察数组，或并排验证两份独立 fixture，都不产生进程重启和持久因果关系。保留局部有效断言、明确名字与范围；全链仍需真实中断点产物作为恢复输入。观察副作用时保留每一次调用和原顺序，不能先用 Map/字典去重，再宣称产品具备幂等。源码调用名称与常量信号名单可以帮助调查，不能代替实际入口行为的证明。

### 接缝必须让不同输入走到真实边界

测试辅助代码的角色转换、分支和模拟时钟也要审查。把新角色默认为旧角色、直接返回期望对象、只修改一个时间整数，都可能让假证据长期保持绿色。接缝只转换输入、注入外部端口并记录实际输出；用受控暂停观察提交/清理前后，不能以源码先后或预写 trace 代替执行。重放测试同时覆盖 Active、已完成和持久终态，不能仅验证活动时重复输入无害。逻辑主体延续与一次工作 handle 的墓碑若冲突，要分清身份再裁决，不能把复活改称恢复。

### 拒绝必须贯穿到有副作用的入口

Decoder 返回 null 不等于整条链 fail closed。沿下游检查 null 是否被当作 Missing，从 durable 身份、默认角色或外部输入路径重新取得授权。对非法可选字段，同时用合法输入作正向控制，并观察实际准入事实与副作用；必要时让“缺失 / 合法 / 非法”的类型区别一直保留到裁决者，不能只在低层识别后丢掉。某段 callback 返回 Result 也不等于错误已向上传递，须在真实组合入口注入拒绝并观察最终结果。

### 接口证明不越级，历史预算有依据

直接调用两个合法处置入口不能证明生产会选对入口；纯计账函数也不能证明完成事件会调用它。将选择、顺序、实际副作用分别接到生产 owner，接缝仅转换输入和记录调用。用受控暂停检验“之前不能发生”，不靠固定时延猜测。历史重放的阈值要有对应时期的合同依据，不把今天的默认值自动施加给旧事实；manual/blocked 是报告还是终态，必须检查 canonical execution，不能只看提示已生成。

### 配置写入与实际消费分开验证

字段赋值成功、依赖版本固定，不等于被依赖系统按此运行。必要能力用安装版和受控端点证明；先隔离标题生成等旁路，再按同一执行身份观察真实请求。遇到重复即取证并结束，避免无意义等待全部故障耗尽。核对对应版本的实际消费链，区分 SDK 与 Host 外层循环；不把改名、伪造错误类别或接受现实现当作修复兼容性。Host 选型和产品所有权需裁决时，保留合同反例，先完成不依赖该选择的工作。

### 统计参照与传输边界不能混为一谈

经验分位数不是未来输出的置信保证。比较检测算法时保留原参数，说明语料、编码单位和触发时点；同一文本改变分块即可改变分数时，先确定度量连续内容还是传输事件，不把夹具分块暗中当合同。检查异步顺序要暂停真实端口：调用后再等待“当前任务”，可能已经等到后续任务，不能证明前一任务先完成。旧测试把违约行为当正例时，保留有效局部事实，按正式条款重新写出可失败的断言。

### 测试自身也必须完成生命周期

断言已完成而进程迟迟不退出，先追查夹具启动后未结束的请求、计时器和任务。让夹具通过真实端口结果结束自己拥有的操作，并等待清理；不要扩大监督时限。真实子进程加上手写“命令在途/未重放”字段仍是假证明：必须实际开始目标操作，再用同一执行的外部观察判断恢复结果。独立证明清单若会成为第二权威，先核对必要性与正式所有者，不因旧测试要求它就重新创建。

### 有界历史要说明失去什么证明

窗口内集合、完整历史和业务投影不能混用。缺失项被视为窗口外时，检查系统实际是否有证据区分“已经过期”与“从未存在”；没有这种证据就记录合同分岔，不虚称同时严格验证两者。验证性能义务先观察真实外部调用，再改变一个必须触发工作的合法输入作正向控制；不以缓存函数名或固定内部调用次数替代“不多做工作”的合同。

### 准入拒绝与真实故障点一起核验

等待正向事件的测试也要观察调用是否已拒绝，否则已废止角色会表现成永不结束的等待。拒绝须在创建子资源或发请求前发生，历史解码兼容不意味着可新建旧角色。注入故障要发生在同一笔工作要求的提交点；完成之后另做一次失败写入，不能证明原完成在写入失败时仍能交付。权限投影、输出渲染、真实队列消费和跨进程恢复分别说明，不能用同一标题补齐未发生的链路。

### 工具名字、配置角色与实际身份分开核对

名字可能经过别名映射再投影权限；某个角色 predicate 拒绝一个名字，并不证明同名 Host 配置没有得到另一角色的权限。分别验证生成配置、请求工具集和真实调用门禁，保留正常身份正例与伪称身份反例。配置面暴露能力时先记录已观察到的事实，再追实际可达性；不能直接宣称越权成立，也不能因底层可能拒绝而抹掉上层合同不符。

### 持久材料与方便夹具分别核验

内存夹具直接携带正文，不代表持久基线只存摘要时也能取得旧正文。以真正落盘、重新读取的材料作输入，观察用户或下游实际拿到什么。涉及前后版本时确认 diff、证书、目标基线来自同一次捕获；分别读取两次，即使单独都正确，也不能证明并发下的一致性。

### 接缝不得补造生产拒绝的事实

测试接缝可以转换数据与注入外部端口，不能猜所属工作、补缺失节点、造证书或直接回答“已经排空”。追查实际调用者，区分生产纯函数、仅供测试的复制实现和真正的宿主连线。撤掉这类伪证明时，同时清理跨包调用、编译登记和发布清单；保留原合同及明确缺口，不用函数名相同来替代因果相同。

### 统一规则先确定必要一致性

一致性约束若影响合法行为、互操作、证书解释或拒绝条件，应在 WHAT 中简短明确；测试 README 只说明用例和证明边界，不能新增验收义务。当前实现选择与原合同冲突时，分别记录事实和待决选项：例如一个事件是否足以完整承载原子消费、运行时目录限制是否允许必要根元数据。第一性原理说明需要守住什么，不自动证明某个格式或实现是唯一答案。

### 精简后再核对作用域与精确性

短句不能省掉决定合格与否的限定。“重放幂等”不一定包含“返回原结果”，“首次”需要说明属于当前哪一个 Life，“有效”不能自动替代 revision 精确相等。完成一轮后由另一人对照原文检查这些细小边界。移出临界区或删除重复副作用前，沿正常与恢复路径确认唯一后续入口，别只看局部 helper。

### 断言完整性由命题决定

2026-09-28用户确认02-008：完整性针对规范要求的结果与副作用。不得以比较全部返回字段代替实际副作用证明，也不能把难测的要求自行划为无关。精确结构或文本合同仍完整比较；真正的布尔合同可精确比较布尔值。范围已裁决不代表全仓断言已审完，不为一般语义判断新造源码扫描或恒真测试。

### 成本测量与完整实现分开

用户按成本授权一个方向时，先分解准备、缓存、计算、存储和外部请求。复制快不代表隔离运行只多同样时间；路径变化可能使编译缓存失效。记录实际样本与未测部分，区分首次初始化和后续增量。用小范围测量支持方案选择，但不把测量脚本当正式回归；方案定稿后，实现与隔离反例仍须另行闭合。

### 上游迁移先确认基线与证据范围

无文本冲突不等于语义兼容。逐项对照新 WHAT、真实接口和测试所声称的行为；不把旧身份、旧工具名或已删除的协议恢复为生产路径。上游自身处于半迁移状态时，保存对应提交和确切断点，将必要适配与未完成的产品迁移分开。局部闭包编译通过不能冒充整库新鲜构建；Draft PR 可交付审阅，但必须明确尚未验证的范围。

### 替代旧协议时保存义务与证据的去向

新规范明确取代旧协议时，逐项区分仍有效的义务、被新所有者承接的规则和正式退役的规则。历史测试可无损归档并保留校验值；归档不是新实现达标，也不能把旧绿色继承为新协议的证明。若替代说明与新WHAT不一致，登记合同缺口，不让测试悄悄维持第二套规则。合并后核对编号索引、影响路径、实际导入和运行入口；重复合并的有效用例只保留一份。

### 真实观察不得被默认成功替代

现场canary必须记录实际版本、实际Hook和终态事实。观察失败或缺失不能用目标版本、默认true、预填completed补齐。比较可变对象时先保存独立原值及必要键序，不能用已经被被测程序修改的引用当答案。由公开事件唤醒完整快照读取，只能证明观察到的事实；手工调用after仍不能证明生产异常路线必然到达after。

观察点也要对应效果发生的位置。后来恢复内存对象不能证明早先落盘的材料仍完整；应在真实执行边界核验清理及异常恢复，并另查公开持久输入与后续历史。普通拒绝也可能返回completed，正常场景须证明真正的业务结果。受控异常或AbortSignal只证明该适配边界，不能代替未消费取消信号的实际业务执行器。

修复参数生命周期时同步核对其它领域的测试，避免能力测试继续要求准入阶段删除提示，反而与Host历史保真冲突。准入验证同对象、原值和顺序保留；实际执行返回后验证恢复；后置回调只能另证幂等。保留权限变化后的真实执行拒绝和原业务结果，不能为旧观察点恢复已经证明有害的副作用。

### 夹具先满足真实前置条件

当前任务的身份、权限根和继承证据优先由生产接口创建，不能手写一个看似合法的子身份而省去活跃父权限。测试取消前，先证明同一次调用仍在途，排除夹具缺少运行能力造成的先行异常；某次失败恰好发生在abort附近，不自动成为取消证据。F#签名与调用匹配也不保证生成后的JS导出名称正确，须编译并加载核对。规范迁移完成、分支已推送、PR已创建和兼容性验收通过分别报告。上游已有构建失败也可能挡住新增代码的验证，不能以“不是本批造成”为由省略这一边界。

### 兼容修复追到实际合同

编译错误先核对真实签名与每个参数的含义，不凭报错位置猜删哪个值。退役接口不能只换名字：按当前 WHAT 确认政策已被谁承接，再清理调用、注册、测试和历史证据。测试没有真正调用的 Surface 不靠空 import 保住登记。持久化返回 Error 时追到实际消费者，区分“停止后续结算”与“整个加载阶段已拒绝”；后台任务以后才报告异常，不等于普通执行前已有屏障。

### 精细合并要比较可区分的行为

三方核对旧施工稿、新上游与合并稿，逐条检查主体、条件、全称范围、数量键、先后顺序、强度、例外和失败后果。必要条件不等于必须发生的结果；“类别可以解释”不等于“唯一所有者解释”；“不通知成功”不等于“不通知任何终态”。删除一句前查实际所有者，完整记录承接去向；不能只搜旧名字便宣称遗漏，也不能把找到相似句当成完整承接。

用具体场景区分两种解释，把政策变化与等义精简分开。WHAT内部或与WHY有歧义时，不按当前实现偷偷选边；记录用户决定。审阅者交叉检查自己未改的部分，并说明自查边界。补正常路径时再试恢复失败、晚到回调和资源重挂等反例；中途快照、主进程退出及前置预检都不能自动证明后续过程已收束。

### 验证入口和统计也需要反例

用既定层级的入口验证相应工作，不能把真实编译塞进单元静默预算后归罪产品，也不能为某个失败临时扩大预算。全量编译可能掩盖独立所有者缺依赖，应保留实际局部闭包证明。测试统计须区分执行入口与共享包装函数的注册位置，并在仓库支持的运行时版本上用真实多文件反例验证；同名测试、重复消费、容器失败和流未排空都不得造成漏计。受统计缺陷影响的历史数字只记录当时输出，不能继承为权威验收结论。

结果流结束、报告排空和操作系统进程退出是不同事实，各在对应生命周期边界核验。运行时丢失取消分类时，保留原始证据及不通过的反例，不能按错误名字猜分类或冒称分类缺口已经修复。

### 新证据前置条件不能掩盖旧失败断言

上游加强归属证明后，先让夹具经真实关联、落地和绑定入口取得合法证据，再触发原本要验证的持久化失败。否则提前返回 Unproven 可能使失败路径根本没被执行；不能把原来的同一异常、零预算、保留flight断言改为忽略结果来过关。新增证明规则也须检查所有例外分支，普通正例通过不代表 repair 等分支没有绕过前置条件。

解决冲突时逐条核对保留正文与承接所有者。重复标题不是第二条规则，不得因删除标题误删完整义务；迁移引用应让读者能找到真正权威的限定和拒绝边界。业务归属与呈现窗口各有自己的“最新”对象，不能把最新 physical message 与最新 semantic turn 混为一谈。

### 计时从实际受监测阶段开始

进程启动、模块加载、规则监测与退出回收各有不同的起点。先记录真实阶段事件，再对照该阶段已有的预算；不能用整个进程的耗时冒充清理耗时，也不能把尚未开始的业务等待算作业务静默。启动本身仍须有界，缺少就绪或被外保护杀死不能算作目标规则正确拒绝。

长属性测试保留样本数量、种子、断言和失败缩减，让完成的真实样本产生可交付的测试结果；日志、轮询和人为心跳不成为进展。物理时限依赖同一机器资源的验证组按正式阶段执行，不能仅因文件不同就并发运行。预热只证明实际执行过的路径，版本查询不证明完整 Host 启动已经预热。

预期失败的用例也要验证证明设施本身可靠。把目标协议拒绝与检查、回收、输出排空的错误分别保留；只有预期原因匹配且设施没有额外错误才算反例通过，不能仅凭错误文本包含一句话。测试读取当前真实数据源，并核验背景事实确实存在；进程结束与输出管道关闭分开观察，清理不依赖管道先关闭，最后实际检查本次拥有的进程组已空。

### 规则分层与并发证明

角色准入与准入后的资源分配各有自己的规则。验证资源键时，使用同一个真实 owner，分别改变 scope、role，并悬置一次实际创建，观察同键请求共享结果而另一个键仍能完成。另核对原 agent、完整端口参数、绑定可见时点与单独移除重绑；只比较两次独立 scenario 的结果不能证明共享 owner 的隔离或 singleflight。

底层 typed Role 的参数覆盖不授予活跃角色权限。保留生产准入的拒绝反例，在 README 写清两组测试各自证明什么，不能为制造两个合法角色而恢复已废止身份。测试清理先排空自己启动的任务，再清空 owner。
