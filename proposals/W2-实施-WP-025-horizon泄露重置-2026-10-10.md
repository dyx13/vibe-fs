# WP-025 horizon 泄露重置 裁决与实施记录（2026-10-10）

- 工作包：WP-025（指南 L639）。波次 W2。本卡先于 WP-020。
- 意见原文：开发者发现 DevOps 在崩溃前的工作内容会泄露到 horizon。如果确实如此，应该重置。结果：horizon 应该为空，join 应该立刻返回无。这不是公理，是推论。

## 证据

1. 旧名册谓词为 `currentProcessHandle || isAbandonedHandle`，且 `isAbandonedHandle` 恒返回真。来源：改动前 `HorizonTool.fs · shouldIncludeHandleInRoster`（本卡施工前的源码观察；该函数现已删除）。恒真意味着 durable 投影里的一切 handle 都进名册，包括上一进程遗留的 Abandoned 句柄——重启后模型看到早已死去的 DevOps/Engineer 仍"在场"。
2. 加载期结算链路已存在：`PluginRecoveryWiring.fs:81` → `LoadRecoverySurface.settleChildRuns`（`LoadRecoverySurface.fs:47`）→ `ChildWorkRecovery.settleOrphanedChildRuns`（`ChildWorkRecovery.fs:123`），对上一 runtime 遗留的活跃子 run 追加 `ChildWorkVoided`。
3. join 侧已有进程所有权判定：`Fork/Host/Join.fs:64 · currentProcessHandle`（`runtime.OwnsAgent`）。
4. durable 投影层的可见性合同：`LinkageProjection.fs:610 · horizonVisible` 保留 Abandoned（后果未交付），`:641 · reportableAbandoned` 让本进程 join 把 abandoned 后果报告一次后 retire。

## 三问

1. 现状防住哪类真实错误？恒真谓词防的是 participant-horizon-011 的"已 durable 建立的 child 在最终后果交付前不得消失"——但它把保护扩到了跨进程，重启后把死句柄当活人展示，并诱导 join 等待永远不会来的交付。
2. 去除后哪条 WHAT 条款失守？一刀切删掉 Abandoned 可见性会失守 participant-horizon-011（本进程内取消后未交付后果必须可见，直至 Join 消费置 Retired）。
3. 更简单的实现？可见性按**进程所有权**切分，不按生命周期切分：投影层保留 Abandoned；呈现层（HorizonTool）与 join 准入共用同一个 `currentProcessHandle` 谓词。跨进程的未决 run 由加载期结算写 `ChildWorkVoided` 关闭。

## 结论

修改。Abandoned handle 的可见性裁决为：

- 本进程内：仍可见（"did not return"），Join 消费后果后置 Retired 移出名册——participant-horizon-011 合同不变。
- 上一进程遗留：不可见、不可 join。load 结算已 void 其逻辑 run；该 run 什么都没产出，就不欠父会话一次交付，`horizon` 与 `join` 对它都为空，直接 `resume` 才是正确时序（crash-reconciliation-018）。

## 实施改动

- `HorizonTool.fs:153`：名册过滤改为 `HandleProjection.horizonVisible handles |> List.filter (HostForkJoin.currentProcessHandle runtime)`。删除恒真的旧谓词。
- `Join.fs:64`：`currentProcessHandle` 成为唯一进程所有权谓词，注释声明 join 准入与 HorizonTool 共用，两个面不可能不一致（host-boundary-021 / EXEC-009）。
- `LinkageProjection.fs`：`horizonVisible`（:610）保留 Abandoned；`reportableAbandoned`（:641）让 abandoned 后果进 join 的 `[[result]]` 批次恰一次，报告后 retire。
- 条款同步：crash-reconciliation [018]（voided run 的 horizon/join 都为空）、delegation [026]（重启收养的空闲伴随句柄只注册身份，不代表有在跑任务，不得让 join 误判等待）、participant-horizon [011]（本进程 Abandoned 可见性边界）。

## 测试（红绿成对）

- `crash-reconciliation/tests/020.test.mjs:56`：活跃子 run 只在 load 结算 void 后离开 horizon 投影。红半段：结算前 `horizonVisible = 1`；绿半段：结算后 `= 0`。
- `crash-reconciliation/tests/020.test.mjs:170`：integrationTest，真实 journal reopen 后 `settleChildRuns` 持久化 void 事实、不产生 completion，重开再结算幂等无重复。
- `participant-horizon/tests/011.test.mjs:27`：重启进程的名册不含上一进程 abandoned child。旧谓词下 Ada 的 "did not return" 会跨重启上榜（红）；新实现 `doesNotMatch /Ada/`（绿）。同文件第一条用例反向守住本进程内 Abandoned 可见合同。
- `delegation/tests/026.test.mjs:195`：`RESTART_PENDING_CHILD_WORK`——重启后 horizon 无 Ada，join 在 1.5 秒超时竞速内返回 NothingToJoin，不挂起。
