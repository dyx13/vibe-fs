# 历史错误与测试数据种子

这份清单用于构造代理工作行为、诊断分类与系统运行回归的数据。最有价值的样本是能区分两种相近情形的材料：相同表象，只有一方违反规则；相同逻辑身份，只有一条时序可以产生效果。仅给规则名、关键词或成功日志，无法检验这种区分。

基线为 `7678c8781`。下面的 12 组修复与调查案例有具体 Git 记录，32 组规则案例来自精简前的规范与现行合同；后者不一概称为已经发生的事故。另附现有 120 条 Enforcer 规则索引。案例中的输入是据来源提出的构造方案，不是原始事故日志。当前工作区未提交的改动不作为已验收行为。

## 样本结构与标注

代理行为样本需要保留能判断前提的轨迹：任务授权、实际读过的规范、工具结果、diff、验证范围和最终报告。只有代码片段，通常无法判断 blind-edit、scope-creep、repeat-until-pass 或 unverified-completion-claim。

系统样本需要固定逻辑身份、物理身份、durable 事件、Host 消息、故障切点和偏序。用屏障控制“已接纳但尚未提交”等位置；纯时序层使用虚拟时钟，不靠 sleep 撞竞态。真实 Host、进程和磁盘边界仍由对应 canary 或物理测试验证。

建议每个种子至少有四份材料：

1. **缺陷样本**：前提完整，违规机制可达，断言应失败或诊断应命中。
2. **正常对照**：只改变决定性条件，正确行为成立，避免仅凭关键词报警。
3. **近邻样本**：症状相同但 owner、身份、请求种类或授权不同，验证规则区分。
4. **证据不足样本**：缺准入、缺 exact identity 或只有猜测；明确返回未证明，不把它标成正常完成。

最小记录可以采用下面的字段；这是数据格式建议，不增加产品规范：

```json
{
  "caseId": "C03-stale-consumer",
  "evidenceKind": "repair-record",
  "sourceCommit": "0fc5bcca4",
  "what": ["managed-session-lifecycle-013"],
  "ruleCandidates": ["snapshot-as-truth", "retry-not-idempotent"],
  "premises": ["同一 exact work", "cold consumer 已确认提交墓碑"],
  "schedule": ["热实例读取旧投影", "冷实例消费并提交", "热实例再消费"],
  "expected": {"fullPayloadDeliveries": 1},
  "mustNotHappen": ["旧投影覆盖墓碑", "第二次正文交付"],
  "pairedVariant": "另一已准入 work 的合法消费"
}
```

`ruleCandidates` 是标注候选，不能仅因系统测试复现某故障就断言代理犯了该行为错误。每条诊断还需要其定义要求的实际工作证据。命中样本应保存决定性原文 span；未命中样本应保存适用的排除条件。

训练与评估按错误机制、源提交和近亲变体分组切分。不要把同一事故改几个 ID 或翻译一次后分到不同集合，否则评估主要测记忆。指标分别计算缺陷检出、正常对照误报、近邻区分、证据不足处理和副作用守恒，不用一项覆盖率代替全部。

## 容易标错的现行边界

- **规则是否成立与 tip 拼写归一是两件事。** [behavior-diagnosis 007](../requirements/behavior-diagnosis/WHAT.md) 保证任何非空 string tip 确定性映射到一条规则，不保证模型选对语义。不要把编辑距离测试当作诊断准确率数据。
- **一般指导不能覆盖具体产品合同。** `unversioned-schema` 不能被缩成“所有 durable event 都必须加 version”；[durable-events 002、009](../requirements/durable-events/WHAT.md) 明确规定 envelope 无版本、词汇 additive。应测试它既有的兼容与拒绝合同。
- **先到获胜不总是错。** [managed-session-lifecycle 007](../requirements/managed-session-lifecycle/WHAT.md) 的 completion 首终态单赋值有正式语义；拿它作 `race-first-wins-semantics` 命中例会误标。
- **没有 event log 不自动等于 snapshot-as-truth。** 规则针对派生视图反过来拥有源事实的权威；数据库行本身是正式 system of record 时，不成立。
- **修改测试不自动等于削弱。** C07 有真实 Host 对照证明旧预期错；删除私有实现 spy 也可能正确。样本必须保留独立依据。
- **数据缺失不冒充空集。** 缺 lease、缺 provider identity、尚未发生 admission、call 没执行，分别是未证明或夹具故障；不能与正式“无 blocker”“无变化”“没有发生效果”合并。
- **退役机制只作历史对照。** `institutional-learning` 与 celebrate/regret 已在 `a66f204dc` 退役；live Rulebook 当前仅来自 shipped built-ins。旧 learned catalog、评分向量、canvas/jq 和旧 Sphinx 公式不得作为现行应通过能力。Sphinx 逐条迁移关系见 [SUPERSEDES](../requirements/sphinx-v2/SUPERSEDES.md)，认知画板边界见 [cognitive-workspace](../requirements/cognitive-workspace/WHY.md)。

## 首批构造顺序

先做 C03、C04、C08、C09、C10、C11，以及 H01、H03、H10、H11、H13、H18。这些案例有明确的身份、时序、字节或次数判据，容易做出能否证错误实现的成对样本。

第二批补诊断近邻：`guess-based-fix` 与 `guessed-not-verified`，`duplicated-truth` 与 `snapshot-as-truth`，`coverage-theater` 与 `weakened-test-to-pass`，`program-counter-state` 与真实业务阶段，`serial-when-parallel` 与必须串行的重叠编辑。每一对都保持表象相似，只改变决定性证据。

其余 120 条规则按完整正文逐条扩展。当前索引提供选题范围；是否做成可执行 regression，仍按对应 WHAT 的受测入口、证据层和已有测试缺口决定。
