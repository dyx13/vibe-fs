# 完整 unit 前后对照（2026-10-26）

四轮平均耗时从 **311.655 秒降至 301.310 秒**，本次观测平均少 **10.345 秒（3.32%）**。但同版两次运行相差 19—37 秒，两个相邻对照分别只省 19.346 秒和 1.345 秒，范围重叠。现在能确认局部定时器清理有效，不能把 3.32% 当成稳定的整套提速保证。

## 实验范围

比较尚未实施优化的方案提交 `ab070405ef71bb94fcc3ffe3d00e59de962dbcce` 与已交付提交 `564b61f32785379b3fc565ede0bf0498175e4695`，包含入口/报告、新增回归和夹具修复的总影响。此前 312.426 秒的基线已经包含 T1，不能当作所有改动实施前的版本；本实验重新取旧版对照。

2026-10-26 晚间按旧、新、新、旧顺序串行运行，版本之间使用同一个洁净工作树路径，通过 Git 检出切换，不改写测试代码。四轮后已恢复 `codex/test-optimization-20261024`。

固定 Node 22.23.4、npm 11.12.1、Apple M3 Pro / darwin arm64、并发 2、unit 静默预算 30000ms、物理 backstop 900000ms、`WXS_ACCEPT_TODO=1` 和 worker 成本诊断。库 gitlink 及构建产物完全相同，每轮都保留 freshness 检查。没有清空系统缓存，机器仍有其他日常应用；ABBA 顺序不能消除所有负载和缓存变化。

计时覆盖正式 unit 入口的子进程生命周期，包括 freshness 和进程回收；外部测量脚本在启动前、退出后采集输入摘要，这部分不计入墙钟。每轮实际执行的入口为：

```sh
NODE_TEST_CONCURRENCY=2 UNIT_VERDICT_SILENCE_MS=30000 \
SUITE_BACKSTOP_MS=900000 WXS_ACCEPT_TODO=1 \
WXS_VERIFICATION_WORKER_DIAGNOSTICS=1 \
WXS_TIER_INTEGRATION=0 WXS_TIER_RELEASE=0 WXS_RELEASE=0 \
node requirements/verification-system/tests/run.mjs
```

实际测量由临时脚本捕获退出状态和新版 IPC，同时保存原始日志；未设置有效文件选集，采用完整发现结果。工具路径及 `WXS_VERIFICATION_NPM_CLI` 与[首次执行记录](../README.md)一致。

这些是文件从启动到排空的时间，彼此并行，不能直接相加当作全套节省。两次新版的总墙钟相差 19.261 秒，较大的变化出现在未修改的生命周期、持久化和委托文件中；本次没有证据把这些额外变化归因于优化。

聚焦入口修复的主要作用是让局部验证实际只跑所选包。本次刻意测完整发现集，因此不会获得“少跑无关包”的收益。完整 unit 的收益目前是小幅观测值，尚未证实稳定的大幅提速。
